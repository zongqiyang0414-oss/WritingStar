# v0.20.0 · 扫描细节与纸底优化

用户提供全能扫描王与本项目的扫描结果，指出本项目较模糊。聊天图可见纸底颗粒、偏灰和细字较软，但两图方向、显示尺寸不同；本轮执行环境没有可读取的附件原文件，因此没有把它们当作同一原照片作像素对比，也没有上传学生图片。

## 修改

- 旧扫描页先把输入缩到2200px，再把校正结果限制为1800px；导出为满足普通照片800KiB预算，JPEG质量最低可到0.58。旧批量导入还有1600px及压缩选图路径。这些限制会丢失整张多栏作业的小字细节。
- 新增统一的`scanQuality.js`：读入长边最多2800px、成片最多2400px，单张扫描独立预算1536KiB，JPEG按0.94／0.90／0.86／0.82尝试，超过预算明确失败，不再继续降低质量。普通照片800KiB规则不变。不确定纸边仍保留完整画面，同样限制输出；小原图不放大。
- 微信通过`canIUse('CameraContext.takePhoto.object.quality.original')`明确支持时取原图，否则保持high；旧批量导入改选原图。依据[腾讯官方API类型](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)的`TakePhotoOption.quality`，不把实时camera的resolution设为未经确认的max。
- 纸面照明估计补偿亮部噪声偏差，校正上限3%；增强暗字连续对比和连通边缘，只在近白中性纸底做范围加权降噪。保留灰阶浅铅笔、细线、红蓝颜色，不做OCR补字。沿用逐段让出UI／Worker／取消／超时与临时文件回收。
- v0.19的直接换纸连续收片、不确定页结束后检查、成片形状独立预览及微信唯一输出路径全部保留；不恢复浮动原生收片层，每批仍最多60页。

提高细节预算会增加单页计算、文件占用，不能承诺手机整次处理时间不变。实时检测保持原小尺寸，拍后暂停送帧、工作线程和可停止处理仍在。正式保存失败保留已完成页与重试能力；后端尚未接入，扫描文件预算为当前前端约定。

## 验证

182项测试、类型检查、H5与官方微信构建通过，含原图能力回退、1100KiB扫描JPEG在高质量下直接通过、超限清理、2400px细线、不确定全图方向／上限、小源图不放大和有噪声纸底的浅铅笔／彩色保护。微信编译后验证连续三页、不确定页保留、通用QR不误丢页、横版／方形最终尺寸、按钮恢复／停止／超时／迟到清理及Worker真实打包往返。

## 手机复测

解压v0.20新包到新目录，在微信开发者工具重新导入／编译／预览，不需重置已有数据。用同一张作业、同一摆位和光照比较新旧结果，放大同一处细字、虚线、浅铅笔；也可将同一张系统相机原照片分别从相册导入，以排除两次拍照的对焦差异。先连续更换3—5张作业，不逐页点确认，最后一次结束；检查按钮与成片形状。

没有iPhone14 Pro Max或微信真机可用，实际镜头对焦、系统原图能力、整次耗时和效果仍待用户复测。当前仅本地交付，按用户要求不上传GitHub、不更新原私有Sites。
