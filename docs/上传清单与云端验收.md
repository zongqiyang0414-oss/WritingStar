## 手机验收路线

### 浏览器预览：先验页面与交互

当前手机入口为[写字星私有预览](https://writingstar.blitheguppy17.chatgpt.site)，使用创建站点的同一 ChatGPT 账号登录，仅该账号可访问。预览站点运行前端与 mock，可体验三种角色、多班级、批阅、反馈和订正，不依赖后端协作者先完成服务。已确认托管部署成功；实际手机访问和操作待用户验收。

GitHub Pages 为一种已准备的发布方式。GitHub Free 支持公开仓库的 Pages；私有仓库使用 Pages 需要相应套餐。若保持私有且账号不支持 Pages，另选静态托管服务，确认其账户和访问规则后部署。仓库私有不自动等于预览网址私有。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

当前无需启用 Pages。若之后改用 Pages，先确认预览的公开范围，再启用发布：

1. 在仓库 Settings → Pages 中选择 GitHub Actions。
2. 在 Settings → Secrets and variables → Actions → Variables 设置仓库变量 `ENABLE_PAGES_PREVIEW` 为 `true`。
3. 在 main 提交或手动运行 `Frontend checks and preview`；检查通过后发布，部署记录提供实际 URL。

工作流默认只检查和保存构建产物，Pages 发布需上述变量明确开启。PR 会检查并保存构建产物；**当前未配置每个 PR 的独立在线预览**。启用 Pages 后，手机固定链接对应 main 最新成功部署的版本。验收修改先更新清单、检查代码，再按用户确定的合入流程更新链接。

Pages 使用站点元数据中的基础路径构建。普通根目录托管运行 `npm run build:h5`；子目录托管运行 `npm run build:h5 -- --base /WritingStar/`。使用 hash 路由，不依赖后端提供页面路由。

手机首次上线后必须实测：链接可访问、图片可加载、切班正确、批阅草稿/发布隔离、订正历史、选择照片、刷新保存。公共预览只使用练习素材。当前本地存储不同步设备；在同一手机浏览器里切换身份完成闭环。更新后刷新页面，旧本地业务数据按迁移规则保留；不要为了更新而自动清空用户记录。

### 微信体验版：验真实小程序

需具备 AppID、开发者权限和微信开发者工具。下载对应提交的 `mp-weixin-<commit>` 构建产物，导入后配置正确 AppID，由有权限的开发者完成预览/上传及体验者设置。微信真机需单独验拍照、临时文件、导航、登录、上传和接口域名；H5 或编译成功不能代替这些验证。

本次不自动接入微信上传密钥，也不宣称体验版已发布。正式登录、图片上传和跨设备数据由后端联调提供。
