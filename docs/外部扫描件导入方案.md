# 手机系统／扫描软件成片导入（调研建议，尚未实施）

2026-11-02，用户提出调用iPhone自带扫描文稿或用户已有软件。目标仍为真实作业清晰、教师只换纸批量采集，写字星负责学生与页码归档。当前无后端和云账号，不以购买付费处理服务为前提。

## 平台边界

- [Apple官方操作说明](https://support.apple.com/zh-cn/108963)确认“文件”和“备忘录”可在自动模式扫描并继续添加页面，整批结束再保存。
- [VisionKit文稿相机](https://developer.apple.com/documentation/visionkit/vndocumentcameraviewcontroller)属于原生Apple应用开发接口。当前微信小程序没有调用它的公开桥接接口；调用普通相机不等于调用系统文稿扫描。如以后做原生iOS客户端，可单独评估该接口和每页图像回传。
- 打开其他App与获取其扫描结果是两件事；不能把URL Scheme、微信受限制的launchApp或相册选择描述为任意唤起扫描软件并自动回传。当前可行路线需要用户在外部软件扫描，结束后导入。
- [uni-app文件接口说明](https://uniapp.dcloud.net.cn/api/media/file.html)区分H5本地选文件与微信聊天文件选择。小程序可采用wx.chooseMessageFile选择微信会话里的PDF等文件，不应把它称为iPhone系统“文件”目录选择器。一个可验证流程是系统扫描保存PDF，作为文件分享到微信文件传输助手，再从小程序选择。

## 已有代码并不等于支持保真导入

`src/components/PaperScanner.vue`目前允许导入JPG／PNG／WebP，仍调用`processScanSource`或`processDeviceScan`，再次缩图、校正、增强和JPEG导出。优质外部成片也可能因此损失细节。项目的`imagePdf.js`用于生成PDF，并没有实现输入PDF的逐页读取。

建议新增“导入扫描件”：

1. 高清图片保留原文件与尺寸，不重新拉伸／增强／压JPEG。另做小预览识学生码，保留现有学生／页码校验，未知码人工匹配；不能把整批PDF按首页学生码归给一个学生。
2. 多页PDF先逐页读取。若页面为独立扫描图，优先评估是否能提取原图并还原页面方向／裁剪；其他结构则需合适的PDF引擎渲染。必须明确实际输入分辨率与结果，不能仅截图系统预览。小程序包体、内存和长批次释放要在实现时验证，不能保证仅加一个选择按钮即可完成。
3. 保留源PDF，逐页预览／移除／归档，按用户真实文件验证二维码、页序、横竖方向、浅铅笔与彩色；每批60页及既有提交规则沿用。来源文件与预览分开，保存失败保留草稿。
4. 用户在外部软件只换纸连续扫描，整批结束后一次导入；有应用切换，不是当前小程序内一键系统扫描。外部软件输出质量、格式和使用收费由具体软件决定，不承诺所有手机一致。

下一步先取得iPhone“文件”实际扫描导出的两三页原始PDF，或现有扫描软件导出的原始高清图片，验证同一处真实细字与浅笔。当前仅调研和记录，尚未实现PDF导入、原样图片导入或原生扫描桥接；未购买服务、未上传GitHub、未更新私有Sites。应用仍v0.20.0，下一轮实际应用改动0.21.0。
