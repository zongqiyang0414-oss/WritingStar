# 文档扫描API接入建议（待真实作业验证）

2026-11-02：用户反馈真实成片仍严重模糊，明确不认可合成样张作为实际质量证明。用户确认没有现成后端服务或云账号。本轮为官方接口调研与接入建议，应用仍v0.20.0，没有开通服务、购买套餐、调用处理接口或上传用户照片。

## 优先试用

建议先试[TextIn文档图像切边增强矫正](https://www.textin.com/document/crop_enhance_image)。该接口提供裁边、形变校正、阴影处理及可选清晰度提升，返回处理图。TextIn属于合合信息体系，参见[官方介绍](https://www.textin.com/about)；其旗下有扫描全能王，但API是否达到用户参考图效果必须实测。

[公开计费页](https://www.textin.com/market/chager/crop_enhance_image)本次读取列出超额价0.1T币／次、1T币等于1元，按此参考50页约5元。最终套餐、试用资格和费用以登录开通时为准，云函数及存储另计。本轮没有购买或申请付费资源。

备选为[腾讯云图像切边增强](https://cloud.tencent.com/document/api/866/133908)，API为`CropEnhanceImageOCR`；也返回处理图片。服务商取舍先以实际铅笔／细字效果决定，而不是仅看功能列表。

## 没有后端时怎么接

可用微信云开发的一段云函数承担调用，不需先建设完整业务后端。先由用户开通自己的TextIn服务和微信云开发环境；凭据配置在云函数环境，前端只调用自有云函数。当前项目身份和作业服务仍是mock，扫描云函数也需要真实登录校验，不能把前端模拟教师身份当成正式权限。

拟议流程：

1. 小尺寸取景帧只负责找纸、稳定判断与自动快门；拍摄后保留相机原文件。
2. 原文件上传私有云存储／调用自有云函数，经服务端调用文档处理服务。不能先走`renderer.read()`的2800px限制或本地增强，再把已经损失细节的成片交给API。若供应商输入超限，由服务端按实测输入预算做必要的单次转换。
3. 服务端保存处理结果并返回本页任务标识、实际宽高、可下载文件引用与处理状态；接口和字段待实施时确认，尚非已有后端协议。供应商返回图不再套用旧本地增强和2400px导出上限。页面缩略图单独缩小，查看／归档使用完整成片。
4. 拍摄和云处理拆为有上限的队列，教师可以继续换纸；待处理、成功和失败有明确状态。网络断开保留原文件和页序，失败可重试；相同页任务应幂等，避免重试导致重复归档或重复付费。整批完成前明确仍未完成的页，不能把“拍到”当成“处理成功”。
5. 保留已有原图、有效学生码防重、每批60页及停止／离页恢复设计。学生匹配仍基于选中纸张，不能通过背景二维码猜学生。自动方向与比例应按原图和真实纸张校验，API未返回可靠信息时不能强行拉伸。

这是待实施架构，不代表已接通或已经可以连续云扫描。前端适配放在`src/services/`，供应商认证和调用只在服务端。网络和服务处理耗时会影响结果等待，云API不保证比当前本地处理更快。

## 下一步验收

先用1—3张真实作业的相机原照片，在选定服务完成试用；同一张输入同时保留原文件和处理结果，比较同一处细字、虚线格、浅铅笔和红蓝批注，确认无笔画缺失、比例变化或内容改写。初次先比较去阴影与锐化模式，不启用手写擦除；清晰度提升选项单独比较，不默认其一定保留每一笔。

通过实际图像质量验收后再改小程序、准备云函数和接入配置，下一轮应用改动按约定升0.21.0。当前缺少账号／凭据／云环境及可读取的未处理相机原照片，未进行供应商实图验证，不能用合成回归代替。继续按用户要求仅本地工作，不上传GitHub、不更新私有Sites。
