## 2026-10-22 浏览器批注后的当前规则

本节取代下方历史段落中“应用AI先确认替换草稿”“允许未评分优秀原图”“优秀区只共享原图”的交互及范围；旧接口和历史数据继续兼容，不据此重置schema 6。当前均为本地mock，不是已约定的HTTP API。

- 微信登录采用一次点击发起的交互。真实前端须调用`wx.login`／`uni.login`取得临时code，后端校验并向微信换取身份、建立可信业务session，再返回绑定状态与权限；AppSecret及会话密钥不能放前端。当前`signIn()`只改变本机模拟账号状态，删除“继续”弹窗不代表已接入微信。正式授权失败、网络错误和登录过期处理待接口联调。
- 作业支持手动填写和题库模板填充。标题必填、要求选填；`assignmentTemplates(role)`返回3个只读内置模板及当前教师个人模板，`saveAssignmentTemplate(input, role)`新增／更新自己的模板，`deleteAssignmentTemplate(id, role)`只删除自己的模板。模板只含标题／要求，不把发布班级或截止时间作为复用后自动发布的指令。个人模板以可选`assignmentTemplates`数组追加schema 6，服务端需按可信教师身份控制读写和持久保存，不能信任客户端`ownerTeacherId`。
- `createAssignments({ title, requirements, dueAt, classIds }, role)`对所有去重后的班级先校验教师任教权限和输入，再一次保存各班独立作业；任一班级无权限、日期无效或保存失败时整批不创建。`classIds`必须非空；`dueAt: ''`明确表示不限截止时间，有值须为未来有效时间，现有日期字符串继续兼容。单班`createAssignment()`保留为包装接口。后端需落实多班事务、重复点击幂等与每班作业ID，不能把客户端逐班成功当成整批原子发布。
- 教师在AI结果页直接核对并可修改两套评分、评语和建议，点“完成批阅”校验量表后经`publish()`保存正式反馈；不再要求先应用AI、保存独立草稿、二次确认再发布。原始AI结果不改写，`draft`及`draftRevision`保留供旧数据和既有服务兼容，但常规界面无独立保存草稿按钮。用户未完成发布的修改不能成为学生正式成绩；学情只计`published`，订正仍须上一版正式发布。后端须校验提交版本、教师权限、量表、并发版本及重复完成，避免迟到AI回调覆盖教师结果。
- 优秀选择仅出现在已完成批阅的详情，`setExcellent()`启用标记须该版本状态为`published`且有正式反馈；设置／取消无需说明确认，取消不删除原图、分数或历史。列表／详情查询也校验已发布状态，旧版未评分优秀标记不会绕过当前规则。仅当前同班在班学生和任教教师可读，管理员不因管理身份自动获得作品权限。
- `excellentWork()`按允许字段返回原图、作者／版本／选择信息及`published`正式评价；同班学生可看书写和写作分数、总体评价、五维评语、批阅建议，继续排除`draft`、原始`aiReview`、提交说明及账号资料。正式后端必须按该投影裁剪响应，不能只在界面隐藏，名单、作品详情和反馈接口都须守住范围。
- 学校切换放在“我的”，只是界面入口变化，不能放宽跨组织权限。示例学校改“甲秀小学”，旧数据迁移仅匹配已知`organization-1`及原名“星河小学”；不覆盖用户自定义名称、不改变组织ID、任教绑定和作品归属。青禾学习中心继续作为另一组织保留。
- 成功、错误和普通提醒居中短时显示并自动消失；涉及未保存内容、照片清空或数据重置的丢失确认保留。底部导航不透明白底及画布层级、微信登录／拍照等平台效果须微信真机另验。当前类型检查、84项测试、H5／微信AppID与WXSS构建检查通过，最终浏览器验证进行中，不能据此宣称后端或真机已联调。
- 练习AI结果仍保留“示例”标识；自选照片只展示真实可用状态，不生成虚构分数。正式AI识别、持久任务队列、费用／配额及多端同步仍由后端提供，前端中“AI可能出错，请核查重要信息。”不替代服务端结果校验。

## 当前服务入口及待提供的接口能力

以下是当前前端使用的模拟方法与所需后端能力映射，**不是已经约定或实现的 HTTP 接口**。

| 当前前端入口 | 后端需要提供的能力 |
| --- | --- |
| `createPrototypeService()` / `read()` | 真实登录后的班级、学生、作业、提交列表；确认查询范围与分页 |
| `createAssignment()` / `createAssignments()` | 标题必填、要求选填、截止可不限；校验全部任教班级后原子创建各班作业，提供幂等及并发控制 |
| `assignmentTemplates()` / `saveAssignmentTemplate()` / `deleteAssignmentTemplate()` | 内置题库只读、个人模板按可信教师身份读写及持久保存，禁止跨教师操作 |
| `submit()` | 保存已上传图片的有序引用，创建提交/订正版本，防止重复提交 |
| `submitForStudent()` | 已授权教师为任教班级在班学生代交，保存学生、实际操作者和有序图片，支持截止后补交；禁止覆盖待批阅提交，发布反馈后创建下一版订正 |
| `setExcellent()` | 任教教师只为正式已发布的提交版本设置优秀，设置／取消直接生效；可信记录选择人及时间，取消不删除原作品或反馈 |
| `excellentWorks()` / `excellentWork()` | 仅向当前同班在班学生及任教教师返回已选且正式发布的作品；详情可含原图与正式评分／评语／建议，单独投影，不返回草稿、原始AI结果、提交说明或账户信息 |
| `saveDraft()` | 历史兼容服务；常规界面无独立草稿保存步骤，未正式发布的内容仍不得对学生公开 |
| `publish()` | 教师核对／编辑AI结果后点“完成批阅”直接发布；校验量表与可信身份，保存正式快照，处理并发修改与重复发布 |
| `feedback()` / `latest()` | 只返回本人有权查看的数据；学生不可获取未发布草稿 |
| `finishAnalysis()` / `manualReview()` | 后端真实处理任务、状态查询/重试、人工批阅入口 |
| `startAiReview()` / `aiResult()` | 本人或有任教权限的老师请求单份AI批阅；学生只取得AI结果，不返回教师草稿 |
| `startAiBatch()` | 当前教师对本作业已提交的最新作品批量入队；跳过未提交、运行中、AI已完成和正式已发布作品；支持仅重试失败与等待结果项 |
| `applyAiReview()` | 历史兼容服务，现主流程直接核对结果后调用`publish()`；不修改原始AI结果 |
| `advanceAiReviews()` | 仅本地模拟队列推进；正式环境必须由后端任务服务持久执行，不能信任客户端计时或作为HTTP接口暴露 |
| `school.js`／`analytics.js` 统计 | 确认统计由后端返回或前端聚合；分页数据不可直接冒充完整统计 |
| 管理员绑定与管理范围 | 服务端授权管理员身份及组织范围；不允许用户自行注册管理权限 |
| `createTeacher()` | 管理员在当前学校新增教师档案，填写姓名／学科、选填手机号及初始任教班级，原子保存档案、任教关系和管理记录；账号绑定、手机号核验和邀请码下发规则待确认 |
| `saveClass()` / `setClassTeachers()` | 校内班级新建／改名、名称去重、任教分配；权限及时失效并保留原作业和反馈署名 |
| `saveStudent()` / `setStudentArchived()` | 校内唯一学号、同名档案区分、归档／恢复；作品和已发布反馈保留 |
| `transferStudents()` | 校内单人／批量调班事务，校验学生当前归属、归档状态、版本冲突与整批成功／失败；保留原班作品和待批阅提交 |

## 2026-10-21 教师代交与优秀作业 · 当前工作环境

以下保留当时实现记录；2026-10-22已将优秀入口限制到完成批阅后，且允许同班查看正式评价，当前规则以上节为准。

- 新增`submitForStudent(assignmentId, studentId, photos, note, role)`，独立于仅供学生本人的`submit()`。教师必须完成绑定并任教作业所属班级，目标学生须在该班且未归档；不依赖当前学生账号绑定，不自动猜测照片与学生的对应关系。选择学生后再确认页序，切换学生会提示并清空旧照片／说明，防止错配。
- 本地体验允许教师补交已截止作业，学生自身仍按截止时间限制。两种入口共同校验1—6页及重复图片、未批阅防重复，反馈发布后生成下一版本；提交与初始AI任务一次保存。`actor: 'teacher'`及可选`submittedBy`记录真实代交来源；AI任务来源为`teacher`，自选照片仍不生成虚构评分。正式截止后补交权限及后台幂等策略待后端确认。
- 每份提交追加可选`excellent: { selectedAt, selectedBy } | null`，旧数据无字段表示未选中；保持schema 6，不覆盖旧作品、反馈或AI结果。优秀与成绩发布分开，教师可分享尚未评分的原作品。订正不会把旧版优秀标记自动转到新版，旧版继续可查看，并可在优秀列表／详情取消。
- 优秀作业按原作业所属班级展示。只有当前同班且未归档的学生、仍有任教权限的教师可读；调班学生失去原班优秀区权限，但自己的旧反馈访问继续遵循原规则。学生不能设置优秀或查看未选中的同学作品。原班老师仍可管理已离班学生原作业的优秀展示。
- 展示投影仅包含作品原图、作业名、作者名、版本、页数及选择人／时间；列表仅附封面，进入详情才读取完整页。教师草稿、AI结果、提交说明、账号和身份字段不向同学返回；同学作品不进入个人反馈／AI入口。取消立即从列表及详情查询中移除，原作品、正式反馈、学情和历史记录保留。
- 当前均为本地mock方法，不是约定好的HTTP API；真实代交权限、图片存储和多端同步、服务端分享范围、选择／取消并发和可信操作人需要后端实现。微信拍照、持久文件及图片放大另做真机验收。

## v0.11.0 AI批阅流程与待确认规则

以下保留原版本记录；2026-10-22已简化为AI结果就地核对／编辑后直接完成发布，不再使用应用草稿确认交互，当前规则以上节为准。

- 学生提交与初始AI任务在一次本地存储内保存，提交后直接进入单份进度页；作业详情和作品记录提供再次查看的入口。AI结果可以在老师发布前由本人查看，教师未发布草稿继续隐藏。管理员无AI结果和批阅权限。
- 每份提交可选追加`aiReview`任务及独立结果快照，不迁移或重写旧作品、旧反馈，也不把既有教师分数冒充AI分数。AI结果采用原双百分制和五维量表，教师可明确确认后应用到草稿；教师改分、写评语、发布和订正均不覆盖AI快照。
- 一键批阅指本次作业全班已提交作品统一入队，每名学生只取最新提交；已发布、已完成AI和处理中作品跳过，不为未提交学生生成作品。2026-10-21新增教师逐名选择学生代交，规则见上节；尚未实现一次上传多位学生的照片并自动分配。
- 本地队列最多模拟三份同时处理，状态分别为排队、识别、双写分析、完成、失败、等待结果、转人工；失败和等待结果可单份或批量重试。任务和尝试次数保存于本机，刷新后可恢复查看；隐藏或关闭应用时本地计时暂停，回到前台继续推进，不能当作真实后台队列可用性的证据。
- 内置练习照片仅返回带“练习作品 · 示例结果”标记的预置评分与建议；自选照片或混合照片返回等待结果状态和空评分，原图片保留，不伪造识别内容。正式结果需从后端可信照片引用、OCR／推理和量表校验返回；示例标记不能由客户端决定正式结果可信度。
- 原有教师草稿在后台AI完成时保持原样。新提交尚无教师修改时可用AI结果初始化复核草稿；应用AI建议会提示替换草稿。老师人工批阅或发布后，迟到的模拟完成不再覆盖教师内容。正式后端还须校验任务ID、提交版本和重试代次，避免过期回调写入新任务。
- AI分数属于学习建议，不计入班级平均分、排名或成长成绩；老师复核发布的反馈才计入原统计。学生订正仍沿用本轮正式反馈发布后再提交的规则，订正创建新版本，旧AI结果、原图和正式反馈都保留。
- 正式异步上传、后台队列、结果通知、并发冲突、批量任务费用／配额和学生提前查看AI建议的服务器策略都待双方确认；当前同步本机mock方法不是约定好的HTTP接口。

## v0.10.0管理流程与待确认规则

- 2026-10-20当前工作环境补充添加教师和本校教师列表。姓名／学科必填、各不超过30字，手机号选填；当前前端仅接受11位大陆手机号并在同校内去重，同名档案可以共存，跨校同手机号不自动合并。这些是本地体验规则，正式手机号地区、教师唯一标识、跨校任教及重复档案合并方案待双方确认。
- 添加教师可选择零个或多个当前学校的班级，不能混入其他学校班级，即使管理员同时管理多校；教师、初始任教和记录一并保存。`phone`为可选联系字段，兼容旧档案；不据此签发登录态或实现P02手机号关联，不自动生成教师邀请码，新增教师的真实账号核验和学习端绑定仍待后端接入。本轮尚未发布至私有预览。
- 当前前端按学校／机构隔离管理列表；任教分配支持本校多名老师。新建班级可暂不分配老师，管理台提示待分配数量。管理员没有新增学校或授予其他管理员的入口。
- 新增与编辑学生要求填写校内唯一学号，归档档案继续占用原学号；同名不同学号可共存。这是前端原型规则，正式学号格式、导入与重复档案合并需后端确认。
- 调班仅支持同校，先选择原班、目标班和学生，再确认整批操作。调班改变当前班级关系，原提交、照片、版本、草稿及发布快照不移动、不改写；当前绑定继续指向同一studentId。原班老师可在原作业的“已离班学生的提交”中继续批阅，学生从记录打开原班已发布反馈。
- 调班后任务列表按目标班级显示，当前实现会包含目标班级已有作业；原班作业不能再新提交。新入班应从哪一份作业开始、是否允许原班订正、历史班级统计及学期归属需双方确认，尚无入班时间或作业名单快照接口。
- 归档学生退出在班名单，不能新提交；已绑定学生仍可读取自己的历史已发布反馈。当前班级人数与统计按在班学生计算，已离班提交单列供教师批阅，不计入当前名单数量。个人成长图继续按当前班级聚合，跨班完整历史通过“记录”查看。
- 当前`read()`仍读取本机完整状态，隐藏入口和模拟服务校验不能构成真实数据隔离；真实API须按登录态裁剪返回内容。管理变更与本地管理记录在一次存储提交内保存，失败不改变内存状态；跨设备一致性与并发控制须由后端实现。
- 兼容升级仅向schema 6追加`administrationVersion: 1`、管理员账户及管理记录，不清空旧学习数据。`MA2026`、`MB2026`是固定虚构管理码；现有学生展示码仍为固定示例，新增学生档案的真实学习绑定待后端接入。

AppSecret、数据库口令、AI 服务密钥和微信上传私钥由对应服务负责人保管，不放入前端源码或可被浏览器读取的环境变量。
