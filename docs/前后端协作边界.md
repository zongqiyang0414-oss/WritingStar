# 写字星 · WritingStar 前后端协作边界

2026-10-16。用户负责小程序前端开发，后端由他人完成。根目录`src/`为完整前端工程，当前源码及原私有手机预览均为v0.11.0；用户已确认手机原型验收通过并授权完整上传GitHub。服务入口为`src/services/index.js`、`mock.js`，AI任务集中在`aiReview.js`、管理能力在`administration.js`，状态类型为`model.ts`。学习端为教师与学生，独立学校／机构管理员负责管理。P01家长端移除已落实，P02教师手机号关联仍待实现。下列服务方法是本地mock接口，不代表已约定的HTTP API；用户验收不代表真实后端／AI／微信真机已联调，恢复依据见[源码恢复说明](源码恢复说明.md)。

## 当前产品范围与关联方向

- 删除独立家长端及家长角色；家长可协助使用学生端完成作业学习，无需额外身份切换。已在v0.9.1私有预览落实，旧绑定、作品与反馈保留，用户待验收。
- 聚焦布置作业、提交作品、批阅、发布反馈、订正和学习记录，不实现缴费等运营功能。
- 管理员独立绑定学校／机构，只管理授权范围内的班级、学生和任教关系；普通教师／学生角色没有管理权限，管理员身份不自动取得批阅和作品反馈访问权限。正式入口及能力必须由后端登录态授权，客户端身份切换和邀请码只用于原型体验。
- 教师手机号拟作为找到老师、关联学习任务的入口；真实登录、学生身份核验、班级关联及异常确认流程均待前后端确认，当前未实现。教师手机号或孩子姓名不能单独作为获取学生资料的凭据，不向未关联用户展示班级学生名单。
- 当前按各身份的模拟绑定选择学生档案；既有`actor: 'parent'`仅为历史提交来源，不是可登录或操作的角色。原图、评分和已发布反馈保留，新提交使用学生身份。

## 当前服务入口及待提供的接口能力

以下是当前前端使用的模拟方法与所需后端能力映射，**不是已经约定或实现的 HTTP 接口**。

| 当前前端入口 | 后端需要提供的能力 |
| --- | --- |
| `createPrototypeService()` / `read()` | 真实登录后的班级、学生、作业、提交列表；确认查询范围与分页 |
| `createAssignment()` | 当前教师向有权限的班级发布作业 |
| `submit()` | 保存已上传图片的有序引用，创建提交/订正版本，防止重复提交 |
| `saveDraft()` | 保存教师五维评分、评语和建议，返回保存结果与版本 |
| `publish()` | 校验量表与角色，发布反馈快照，处理并发修改与重复发布 |
| `feedback()` / `latest()` | 只返回本人有权查看的数据；学生不可获取未发布草稿 |
| `finishAnalysis()` / `manualReview()` | 后端真实处理任务、状态查询/重试、人工批阅入口 |
| `startAiReview()` / `aiResult()` | 本人或有任教权限的老师请求单份AI批阅；学生只取得AI结果，不返回教师草稿 |
| `startAiBatch()` | 当前教师对本作业已提交的最新作品批量入队；跳过未提交、运行中、AI已完成和正式已发布作品；支持仅重试失败与等待结果项 |
| `applyAiReview()` | 老师明确确认后将AI建议复制到草稿，再人工复核和发布；不修改原始AI结果 |
| `advanceAiReviews()` | 仅本地模拟队列推进；正式环境必须由后端任务服务持久执行，不能信任客户端计时或作为HTTP接口暴露 |
| `school.js`／`analytics.js` 统计 | 确认统计由后端返回或前端聚合；分页数据不可直接冒充完整统计 |
| 管理员绑定与管理范围 | 服务端授权管理员身份及组织范围；不允许用户自行注册管理权限 |
| `createTeacher()` | 管理员在当前学校新增教师档案，填写姓名／学科、选填手机号及初始任教班级，原子保存档案、任教关系和管理记录；账号绑定、手机号核验和邀请码下发规则待确认 |
| `saveClass()` / `setClassTeachers()` | 校内班级新建／改名、名称去重、任教分配；权限及时失效并保留原作业和反馈署名 |
| `saveStudent()` / `setStudentArchived()` | 校内唯一学号、同名档案区分、归档／恢复；作品和已发布反馈保留 |
| `transferStudents()` | 校内单人／批量调班事务，校验学生当前归属、归档状态、版本冲突与整批成功／失败；保留原班作品和待批阅提交 |
| `administrationEvents` | 由服务端可信记录操作者、学校、时间和操作；本地记录不能代替正式审计 |

数据类型参考 `src/services/model.ts`，量表参考 `src/services/rubric.js`。前端目前同步读取本地完整状态；接入网络 API 时需在服务层及必要的界面加载状态处做异步适配，不能只替换请求地址。

当前传入的 `role`、模拟账号绑定和身份切换均为展示约定。正式后端必须从登录态判断用户、班级及学生权限；不得信任客户端传入的角色。

## v0.11.0 AI批阅流程与待确认规则

- 学生提交与初始AI任务在一次本地存储内保存，提交后直接进入单份进度页；作业详情和作品记录提供再次查看的入口。AI结果可以在老师发布前由本人查看，教师未发布草稿继续隐藏。管理员无AI结果和批阅权限。
- 每份提交可选追加`aiReview`任务及独立结果快照，不迁移或重写旧作品、旧反馈，也不把既有教师分数冒充AI分数。AI结果采用原双百分制和五维量表，教师可明确确认后应用到草稿；教师改分、写评语、发布和订正均不覆盖AI快照。
- 一键批阅指本次作业全班已提交作品统一入队，每名学生只取最新提交；已发布、已完成AI和处理中作品跳过，不为未提交学生生成作品。暂未新增教师代学生批量上传；代上传的照片与学生匹配、来源标记、允许代交范围需另定。
- 本地队列最多模拟三份同时处理，状态分别为排队、识别、双写分析、完成、失败、等待结果、转人工；失败和等待结果可单份或批量重试。任务和尝试次数保存于本机，刷新后可恢复查看；隐藏或关闭应用时本地计时暂停，回到前台继续推进，不能当作真实后台队列可用性的证据。
- 内置练习照片仅返回带“练习作品 · 示例结果”标记的预置评分与建议；自选照片或混合照片返回等待结果状态和空评分，原图片保留，不伪造识别内容。正式结果需从后端可信照片引用、OCR／推理和量表校验返回；示例标记不能由客户端决定正式结果可信度。
- 原有教师草稿在后台AI完成时保持原样。新提交尚无教师修改时可用AI结果初始化复核草稿；应用AI建议会提示替换草稿。老师人工批阅或发布后，迟到的模拟完成不再覆盖教师内容。正式后端还须校验任务ID、提交版本和重试代次，避免过期回调写入新任务。
- AI分数属于学习建议，不计入班级平均分、排名或成长成绩；老师复核发布的反馈才计入原统计。学生订正仍沿用本轮正式反馈发布后再提交的规则，订正创建新版本，旧AI结果、原图和正式反馈都保留。
- 正式异步上传、后台队列、结果通知、并发冲突、批量任务费用／配额和学生提前查看AI建议的服务器策略都待双方确认；当前同步本机mock方法不是约定好的HTTP接口。

## v0.10.0管理流程与待确认规则

- 2026-10-20当前工作环境补充添加教师和本校教师列表。姓名／学科必填、各不超过30字，手机号选填；当前前端仅接受11位大陆手机号并在同校内去重，同名档案可以共存，跨校同手机号不自动合并。这些是本地体验规则，正式手机号地区、教师唯一标识、跨校任教及重复档案合并方案待双方确认。
- 添加教师可选择零个或多个当前学校的班级，不能混入其他学校班级，即使管理员同时管理多校；教师、初始任教和记录一并保存。`phone`为可选联系字段，兼容旧档案；不据此签发登录态或实现P02手机号关联，不自动生成教师邀请码，新增教师的真实账号核验和学习端绑定仍待后端接入。本轮尚未发布至私有预览。
- 当前前端按学校／机构隔离管理列表；任教分配支持本校多名老师。新建班级可暂不分配老师，管理台提示待分配数量。管理员没有新增学校或授予其他管理员的入口。
- 新增与编辑学生要求填写校内唯一学号，归档档案继续占用原学号；同名不同学号可共存。这是前端原型规则，正式学号格式、导入与重复档案合并需后端确认。
- 调班仅支持同校，先选择原班、目标班和学生，再确认整批操作。调班改变当前班级关系，原提交、照片、版本、草稿及发布快照不移动、不改写；当前绑定继续指向同一studentId。原班老师可在原作业的“已离班学生的提交”中继续批阅，学生从记录打开原班已发布反馈。
- 调班后任务列表按目标班级显示，当前实现会包含目标班级已有作业；原班作业不能再新提交。新入班应从哪一份作业开始、是否允许原班订正、历史班级统计及学期归属需双方确认，尚无入班时间或作业名单快照接口。
- 归档学生退出在班名单，不能新提交；已绑定学生仍可读取自己的历史已发布反馈。当前班级人数与统计按在班学生计算，已离班提交单列供教师批阅，不计入当前名单数量。个人成长图继续按当前班级聚合，跨班完整历史通过“记录”查看。
- 当前`read()`仍读取本机完整状态，隐藏入口和模拟服务校验不能构成真实数据隔离；真实API须按登录态裁剪返回内容。管理变更与本地管理记录在一次存储提交内保存，失败不改变内存状态；跨设备一致性与并发控制须由后端实现。
- 兼容升级仅向schema 6追加`administrationVersion: 1`、管理员账户及管理记录，不清空旧学习数据。`MA2026`、`MB2026`是固定虚构管理码；现有学生展示码仍为固定示例，新增学生档案的真实学习绑定待后端接入。

## 保留的业务约定

- 书写与写作各 100 分；五维上限分别为 10/60/10/10/10、10/20/30/20/20，量表版本为 `legacy-backend-five-thinking-v1`。
- 教师草稿仅教师可见；学生可提前看本人独立AI学习建议，老师发布后再查看正式反馈。订正生成新版本，保留旧作品、AI结果和已发布反馈。
- 工作台按当前班级进行中作业统计；学情覆盖当前班级全部作业，均分采用每位学生每份作业最近一次已发布反馈。未发布草稿不参与。
- 当前 mock 数据只在当前浏览器保存。电脑和手机、不同浏览器之间不共享数据；不同角色的体验需在同一个浏览器里切换完成。

AppSecret、数据库口令、AI 服务密钥和微信上传私钥由对应服务负责人保管，不放入前端源码或可被浏览器读取的环境变量。
