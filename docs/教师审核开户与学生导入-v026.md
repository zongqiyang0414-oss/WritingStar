# 教师审核开户、学生导入与模板排版 · v0.26.0

2026-11-04。本轮将教师申请审核作为开户入口，学生由教师导入后领取账号密码；学习端只显示教师和学生。当前实现为本机前端原型，审核、登录和凭据均未连接真实后端。

## 当前流程

1. 教师在“申请教师账号”填写姓名、学校、联系电话三个必填项，可附教师证明。证明支持 JPG、PNG、WebP 图片或 PDF，单份不超过 2 MiB。
2. 提交后显示待审核状态，尚未生成账号。平台模拟审核可通过或退回；退回须填写原因，申请人可补充材料重新申请。通过后创建教师档案并颁发唯一账号和初始密码，重复审核不会重复发号。
3. 教师使用账号密码登录，在“我的”进入“班级管理”或“学生管理与导入”。新建班级自动加入自己的任教范围，教师仅管理自己的班级和学生，不能自行创建其他教师或调整其他教师的任教授权。
4. 教师选择目标班级后上传名单，先核对预览与逐行问题，再确认整批导入。学生档案和登录账号密码一起保存；任一行无效或保存失败均不产生部分学生、账号或管理记录。
5. 导入完成显示账号和初始密码，可复制名单或导出 CSV，交给对应学生。重新进入导入页可再次导出本班在班学生的已有账号，不重新生成或轮换密码。学生使用老师发放的账号密码登录。

“展示设置”中的账号、平台审核和证明预览仅供本机演示。模拟审核通过后可在此查看颁发凭据；联系电话只是申请资料，当前没有短信、电话通知或真实账号发放服务。

## 名单文件与校验

| 项目 | 当前行为 |
| --- | --- |
| Excel | 支持 `.xlsx`、`.xls`；合并可见工作表核对，隐藏工作表不导入。 |
| Word | 支持 `.docx` 普通表格；旧 `.doc` 明确提示另存为 `.docx`。 |
| 表头 | 前20行内有“姓名”列，可另有“学号”列；保留来源工作表／表格和行号供查错。 |
| 容量 | 单份文件不超过5 MiB，每批最多500名学生；限制解压体积和表格范围。 |
| 空缺与重复 | 姓名必填；学号可选，未填时自动分配。校内已有学号、文件内重复学号、无法区分的同名学生需先修正，不静默跳过或合并。 |
| 范围 | 目标必须为当前教师本人任教班级。学生端和其他班级不可导入或领取账号。 |
| 导出 | CSV含姓名、班级、学号、账号、初始密码；复制为表格文本。重新导出保留原凭据。 |

名单在设备本地解析，没有上传至云端。Excel使用 `xlsx`，Word文档解包使用 `fflate`；微信端使用文件选择及文件系统接口，H5使用浏览器文件选择。

## 角色、迁移与原有业务

独立管理员角色和登录入口从产品界面撤下。旧管理员的学校和班级范围转为普通教师档案供账号登录；旧管理员内部方法仍用于历史兼容，不作为新产品的第三种角色。既有 schema 6、教师／学生关联、学生档案、作业、原照片、评分与反馈保留，通过可选的 `accountRegistrationVersion`、`teacherApplications`、`loginCredentials` 追加账号信息，不要求恢复初始数据。

新增学生仍遵循既有名单规则：只接取进行中的作业，已完成和已截止的历史作业不因导入新增参与人；名单和专属答题卡继续原子保存。v0.25的批阅定位、打回、连续扫描、原像素PNG、补光和PDF逐页归档保持原有流程。

## 模板与编辑区域

A3横向方圆格正反两页、正文格子及原9／6定位点保持。原题目栏中央的大二维码改为题目栏顶部三个68px方码，按A3实际尺寸约24mm，每个均保留四模块白色静区。三个码绑定同一作业、学生和当前页码，作用是提高取景时读到有效码的机会，不表示三名学生或三个页码。

标题使用20px文字并换行，题目要求使用14px多行文字；编辑器提供更大的标题和要求输入区域。可选题目插图等比绘入正面原思维导图区域，未选图时保留原区域。过长内容在纸面以省略号和“完整要求请查看学生端本次作业”提示，不覆盖格子或定位点；学生端仍保留完整题目和要求。个人题库模板一并保存可选插图。

扫码优先查看顶部小码，同时保留旧中央大码位置的兼容路径。程序解码检查不代替实际打印、手机对焦和扫描距离验收；缩小后是否满足真实课堂取景条件仍需纸张与手机复测。

## 前后端协作边界

当前 `submitTeacherApplication`、`reviewTeacherApplication`、`loginAccount`、`importStudents`、`studentCredentials` 均为本机模拟服务方法，字段和方法名不代表已约定HTTP API。模拟 `platform-demo` 标记只是演示隔离，不能作为正式平台审核权限；客户端角色、教师ID或班级ID也不能作为可信授权依据。

正式后端需共同确认：

- 教师申请、证明上传与访问范围、补充材料、审核结论和审计记录；只有平台审核人员可颁发教师账号。
- 教师账号登录与可信会话；以服务端教师身份校验班级范围，学生仅访问本人学习数据。
- 导入预校验、重复提交幂等、学生档案与账号的事务创建，以及进行中作业的名单与答题卡同步。
- 密码哈希、初始凭据的安全发放和领取权限、首次使用／密码重置规则；正式系统不能照搬原型明文凭据存储和展示工具。
- 申请进度和颁发结果的真实通知渠道、跨设备状态及错误／会话过期恢复。

本轮未实现生产数据库、云端证明存储、短信通知、真实密码安全或跨设备账号同步。后端接口、通知与凭据策略须与协作者确认后接入。

## 开发检查与用户验收

账号申请／通过与退回、权限范围、存储失败回滚、旧数据迁移、导入文件与凭据、模板绘制及旧扫码兼容的针对性验证由本轮开发记录补充。类型检查、全量业务测试、H5／微信构建和浏览器流程的最终结果见[交付状态](云端交付状态.md)；本说明不将开发检查记为用户验收或微信真机通过。

建议手机验收：

1. 提交三项个人信息及可选教师证明，确认未审核时不能取得教师账号；退回后修改，审核通过后以颁发账号登录。
2. 教师新建班级，分别用Word和Excel名单导入；有重复或缺项时修改文件，核对无误后导入并领取凭据。
3. 退出并用其中一名学生账号登录，确认只看到自己的任务与作品；教师重新登录后可再次导出原班账号。
4. 创建含长标题、多行要求和插图的作业，查看／打印正反两页；确认题目清晰、格子及定位点完整，分别遮住部分顶部码仍能识别当前学生与页码。
5. 复测旧已发答题卡、原作品与反馈、连续扫描和PDF上传，确认本轮身份变化未丢失历史内容。
