# v0.14.0 · 拍后处理与固定导航 · 2026-10-30

## 用户问题与改动

用户反馈拍照后的裁剪等处理也很慢，并要求滚动到下面仍可看到“返回”和底部bar。本轮先将bar理解为工作台／学情／我的底部导航（已发澄清，未收到文字回复）；若后续明确指发布操作栏，按后续指示接续。

- scanProcessing.js统一拍摄页、H5相册和微信相册的像素处理。专属码先从裁选纸张的上方区域识别，失败仍全图回退；保留任意位置／反色码。普通文档扫描不做学生码搜索。只有角标估计可能裁掉二维码静区时才重试原图，可靠纸边不重复跑两轮大图。
- 透视坐标改为逐行／逐像素增量计算，保留双线性采样、1800px默认输出上限与微信导入1600px上限；不通过降低尺寸掩盖耗时。纸面增强缓存插值坐标；计算超过约10ms后让出UI，代替固定每48行等待一次。
- H5取景框改用矢量图，省去每帧PNG读回和编码；微信仍用cover-image，但边框导出与识别分开，不能等待导出完成才收下一帧。纸张移开、移动或退出后不恢复迟到框。
- 有返回的标题行滚动吸附到顶部，教师／学生共用，管理员子页也保留返回；底部导航继续固定，页面底部留白含安全区，末项内容不会被遮住。未改返回历史、作业下发和保存规则。

- 44项相关测试通过：含新增采样梯度、专属码区域、全图回退、反色码、裁选纸张／背景码隔离、跳过无关识别、取消与RGBA复制；原二维码归档、同页锁和多选测试保留。
