# v0.18.0 · iPhone 扫描成功后按钮无响应

2026-11-02（北京时间）。用户在 **v0.17.0 微信预览包、iPhone 14 Pro Max** 上反馈：扫描成功后，查看图片／拍照等按钮无法点击，原生摄像头预览继续运行。

本轮按用户最新要求只在本地修改和交付微信包，**暂不上传 GitHub，不更新原私有网页预览**。旧自动发布约定在当前暂停指令下不执行。

## 调整

- 微信端移除位于原生相机上方的浮动 `cover-view` 收片动画，改为现有缩略图到片反馈；手拍成功直接查看结果，自动扫描继续取景。网页端继续使用原收片动画。此举消除该浮动原生层参与命中测试的可能；没有真机证据证明它是本次故障的唯一原因。
- 原生帧入口增加背压：一次只处理一帧，识别完成后留出180ms响应间隔，丢弃多余帧，避免相机持续送帧挤占按钮事件。拍后像素处理期间停止帧监听，成功后按当前页面状态恢复；不停止正在显示的原生相机预览。
- `scanAsync.js` 为拍摄、图片加载、画布导出和文件回调增加有界等待。主要原生操作12秒、画布初始化／文件大小读取5秒；每张图片处理45秒兜底。超时恢复按钮并提示重试，避免一直留在busy状态。
- 处理中可点击“停止处理”。取消使当前任务失效、停止Worker、关闭相机并释放操作锁；已扫描页面保留，仍可查看。相册剩余队列暂停，可点击“继续处理所选图片”恢复。
- 取消读图后不再写回共用画布；迟到拍摄／JPEG临时文件清理，不追加成片、不释放新任务的锁。保存回调和回滚清理也设置超时，已完成的页面不因停止当前处理而删除。

## 手机复测

1. 下载v0.18.0 ZIP，解压到新目录后导入微信开发者工具，重新“编译→预览”；不要继续扫描旧v0.17二维码，不需清空已有数据。
2. 自动扫描一页后点右下角缩略图，查看全图，再返回继续扫描；重新手拍一页，检查按钮、页数和结果。
3. 确认微信改为缩略图到片反馈，没有覆盖相机的飞行图片；网页动画不是本次手机验证依据。
4. 处理中点“停止处理”，检查已有页仍可查看；多选相册后停止，再恢复队列。切后台再回来，检查没有迟到重复页。
5. 若仍出现按钮无响应，需要继续核对卡住时的顶部文案／页数、缩略图反馈是否已消失及微信版本，不能仅根据原生摄像头仍运行就认定整个JS线程正常。
