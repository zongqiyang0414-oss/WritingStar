# v0.21.0 · 自动拍照与原图留存

用户最新决定：保留自动框住纸张、稳定后拍照，以照片方式上传和展示；照片处理留给未来模型输入副本。停止把教师查看的照片加工为扫描件，不再以合成图证明真实清晰度。当前仍仅本地交付，不上传GitHub、不更新私有Sites。

## 行为

- 自动框选、约1.2秒稳定等待、直接换纸、同页锁定、有效专属学生码防重、每批60页继续保留。边框只辅助取景，拍到的是完整照片，包含画面里的背景；不会按框裁切、拉正、改变比例、去阴影、锐化或重新导出JPEG。
- 拍后可看原照片、双指放大／拖动、查看平台全图，继续拍摄或删除本页；整批结束一次添加。移除调角、A4／正方形选择和形状小预览。手拍和相册也不再弹调角确认，边缘不确定时仍保留照片；学生码不确定可在收件箱人工核对。
- 普通作品上传、扫描页相册添加、答题卡收件箱的批量导入全部保留所选文件。原800KiB自动压缩不再执行；普通选图沿用最多6页，单张输入上限20MiB，超过上限明确拒绝，不自动降质。扫描收件箱仍最多60页，微信原生单次相册选择最多9张。
- 教师看的是当前相机／系统选图实际返回的照片。相机本身的对焦、曝光、分辨率和平台输出仍影响清晰度；不宣称能恢复拍摄前已丢失的细节，也不把自动拍照称为系统原生文稿扫描。

## 实现

`src/pages/scan/index.vue`使用`renderer.readAnalysis()`生成最多1600px分析副本，仅用于纸张区域和学生码识别。调用处理器时明确`identifyOnly:true`；只在副本中提取已检测纸张／四角标记区域，不做增强。源像素不被改写，正式`photo.url`始终指向原文件。拍摄边缘信息仅记录在可选`captureCorners`中，不作为图像变换。非学生通用二维码不参与身份防重，未知区域不按背景码归档。

微信拍摄或选图的临时路径可能复用，因此用`copyFile`为每页建立独立原文件，保留扩展名与二进制内容。整批成功后将该文件所有权交给收件箱，页面释放不删除正式文件，也不再为整批复制一次。取消交付保留原件可重试；迟到复制清理、不覆盖已完成页，沿用停止／超时和相机帧背压。JPEG生成、形状预览等旧辅助函数仍保留于工程／历史测试，当前保存与展示路径不调用。

H5相册的临时Blob转换为原始字节的data URL后再交付，避免离页释放Blob导致已添加图片失效；没有解码后重新编码。浏览器实时拍照优先使用可用的`ImageCapture.takePhoto()`实际静态照片，其他浏览器保存实际视频帧的完整尺寸PNG，不额外有损压JPEG；视频帧模式的分辨率受浏览器相机流限制。相机原生／小程序与浏览器不能相互代替真机验收。

`photos.js`保留普通照片原文件，选择失败或超过大小限制不缩图；多张保存中途失败只回收本次新文件。`documentScanner.js`与`devicePaperScanner.js`的批量导入也只保存原图，识码使用独立小画布，通用码清空、有效学生码仍归档；不写回替代像素，不导出JPEG。

## 模型边界

模型不一定需要额外处理，取决于实际模型的尺寸、方向和版面要求。需要时创建独立输入副本，记录它与原图的关系；教师／学生展示和正式原作业始终使用原图，不能用模型副本覆盖。`Photo`新增可选`original`、尺寸和取景角点元数据，旧作品兼容，不重置已有数据。

当前仍为前端mock，没有接入真实后端／图像API／批阅模型；本轮没有实现模型预处理服务。原图文件会比压缩扫描件大：微信按文件保存，设备空间不足明确报错；H5扫描草稿使用IndexedDB，正式原型提交仍受原有localStorage容量限制，失败保留草稿，后端接入时应独立存图片与业务元数据，不能重新压缩来掩盖容量问题。

## 验证与手机复测

- 185项测试、类型检查通过，包含只识码时源数组不变／不读背景码、12MiB普通原图不调用压缩、PNG二进制复制／取消与交付后留存、多文件失败回收及原有业务规则。
- H5／官方微信构建通过。实际编译的小程序在原生API模拟下，直接换纸连续3页、同页不重拍、通用码保护、查看后继续手拍、取消／超时／迟到清理及原生手势通过；禁止任何照片JPEG导出。模拟相机重复使用同一临时PNG路径，4页仍保留各自原文件内容、3024×4032尺寸及PNG格式，整批交付不再次复制；这是编译链路验证，不是iPhone实机结果。
- 浏览器实际相册选择3张文件，通过SHA256比较返回查看图与所选文件的字节一致；其中大图为3000×4000、4,724,125字节，完整尺寸和格式保留。停止／迟到解码不收页／恢复队列及超限不半批导入通过。输入是程序测试样本，只用于验证文件未被处理，不作为真实作业清晰度比较。界面记录见[相册原图](../outputs/scan-album-original-v021-20261102.png)。
- 浏览器真实二维码像素的同页锁、直接换下一张、放回已收页防重、手拍、学生归档、60页、按序提交和相机释放通过，正式提交保留查看时同一原图及960×720尺寸。真实触屏输入验证双指放大、拖动、全图预览、旋转／翻页复位及收片反馈取消；[拍照](../outputs/v021-scan-auto-20261102.png)、[原照片查看](../outputs/v021-scan-result-20261102.png)、[收件箱](../outputs/v021-scan-inbox-20261102.png)、[触屏查看](../outputs/v021-scan-zoom-20261102.png)仅为功能界面样本，不证明真实拍摄效果。

手机请用v0.21新包重新导入、编译并生成预览码，无需清空数据。连续更换3—5份作业，查看完整照片与放大字迹，再整批添加；从相册选一张系统相机原照片，核对没有自动裁剪、变形和滤镜。iPhone14 Pro Max实际拍摄质量、操作响应与文件占用仍需复测。
