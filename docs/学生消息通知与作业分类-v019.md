# v0.19.0 · 学生消息通知、作业分类与教师批阅文案

2026-11-02，接续GitHub main 的1e97226；保留schema 6、既有本机数据、教师一次重交许可、AI失败重试和方向校正规则。

## 最终行为

- 首页原“有新作业，去看看”替换为消息通知，显示最近3条和未读数；“查看全部”进入完整通知页。新布置的作业／需重交打开对应作业详情，教师批阅完成打开本人反馈页。点击成功标记已读，刷新后保留；返回时保留作业筛选和滚动位置。
- 通知由真实原型状态的作业createdAt、当前重交许可allowedAt及教师发布publishedAt派生，不另生成虚构消息；AI结果完成不会冒充教师反馈。仅本人可读取和更新已读状态，稳定事件ID去重，存储失败回滚。新作业／重交仅限学生当前在班范围，已离班学生保留本人已有教师反馈；新提交产生后不再以旧结果通知展示过期成绩。
- 新增五个互斥分类及数量：未提交、已提交、已批阅、需重交、已截止，默认未提交。需重交优先于已批阅／已截止；已经提交或完成教师批阅的作业不因截止而换入“已截止”，已截止只收未提交且期限已过的作业。AI处理、失败和等待教师反馈均属于已提交；具体AI状态仍在详情单独显示。
- 需重交的任务主按钮为“重新提交”，进入作业详情，沿用原先教师许可的一次上传机会和越过截止时间规则。已批阅任务仍可查看反馈。
- 学生首页、作业详情、提交页、反馈、记录、成长、趋势和侧栏引导不再出现教师“审核”文案，改用“已提交”“教师批阅中”“等待教师反馈”“教师已完成批阅”等对应表述。教师端的审核操作和统计口径保持。

## 数据与边界

新增可选`studentNotificationReads[studentId][notificationId]`，不改schema或重置学生资料；通知模型只传标题、事件类型、目标ID、时间和已读标记，不带照片、草稿或未发布成绩。本轮为站内消息，不发送邮件／微信订阅消息或浏览器推送。

现有服务仍是MockService和本机存储。本轮可验收站内通知和已读行为；正式多人后端需要以服务端事件、鉴权和读状态接口接入，当前前端结构不构成已约定HTTP API。
