## 继续云端开发

GitHub源码和私有预览已就绪，本轮已在附加的WritingStar云端环境完成构建和部署。下方保留环境创建方法；上传仓库本身不会自动创建云端环境。

在网页或桌面端选择 Work in → Cloud → Select environment → Create environment，选择 WritingStar，设置下面的安装和检查命令，完成并发布环境。之后手机可选择该环境继续提出修改。[OpenAI 官方云端说明](https://learn.chatgpt.com/docs/cloud)

- Node：`.nvmrc` 中的 24.15.0。
- 安装：`npm ci --no-audit --no-fund`。
- 当前预览检查：`npm run verify:preview`、`npm run test:preview`。
- 当前预览打包：`npm run build:preview`；本地运行：`npm run dev:preview`。
- 历史uni-app工程另用`npm run type-check`、`npm test`、`npm run build:h5`、`npm run build:mp-weixin`检查，不能用其产物覆盖当前预览。
- 不需要后端或 AI 密钥；读 `AGENTS.md`、README 和验收表后继续开发。

后续默认在当前工作环境修改源码及验收表并运行对应检查。用户要求上传GitHub时，协作代理同一任务中完成版本同步、对应预览打包、现有私有Sites部署与成功确认，无需单独询问部署；文件完全相同且已有成功部署时核对并沿用该部署。当前GitHub Actions仍只检查和保存产物，未配置独立Sites发布工作流，也没有每个PR的独立预览；同一任务的部署由具备Sites工具的会话完成。若用户明确要求只上传、不部署，则遵从该次限制。
