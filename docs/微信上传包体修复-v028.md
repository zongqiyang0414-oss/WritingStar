# v0.28 · 微信预览包体与代码质量修复

用户在 Windows 微信开发者工具2.02.2608080预览v0.27时报告：`pdf-import source size 4851KB exceed max limit 4096KB`。附图同时显示主包超过1.5M建议、PDF专用JS留在主包、JS未压缩、组件未按需注入及图片超过200K。

原检查只统计构建目录原始字节。旧配置开启ES6转换但关闭JS压缩，已预构建的PDF引擎仍会交给开发工具转译；这不能覆盖上传编译后体积。本次同时修复以下环节：

- 在受版本管理的manifest配置里开启JS/WXML/WXSS压缩、`lazyCodeLoading: requiredComponents`。应用仍正常进行ES6编译，PDF/名单引擎及扫描Worker则通过`babelSetting.ignore`排除重复转换。构建检查强制验证这些设置。
- PDF专用canvas适配器移入`src/pdf-import/pdfCanvas.js`，主包不再残留该文件。
- 答题纸底版单独放入`paper-assets`分包，查看/打印时先加载再读图。两张底版保留原始文件字节，不压缩或缩小书写格；加载失败明确提示、可重试。
- 仅微信构建生成800px横版Logo（约71KB）；原始品牌图片和H5资源保留。所有小程序图片低于200KiB，主包构建目录低于1.5MiB。
- 官方上传白名单不包含PDF字体的`.pfb`和字形映射的`.bcmap`，改为合法`.br`资源，通过微信`readCompressedFile`解压恢复原始字节。PDF引擎保留完整依赖许可证导出，资源许可也随压缩文件保留。H5继续使用原资源。
- 新增官方SDK离线编译后包体校验；统计转换后的JS及生成的辅助文件，保守保留所有原资源计入。每包保持项目2MiB上限（低于用户报错4MiB），主包还需小于1.5MiB。检查字体/映射未被SDK过滤、底版文件字节完全相同。

## 验证

241项测试、类型检查和双端构建通过。PDF字节解压后矢量模板渲染与标准Canvas2D逐像素一致，四页扫描件/两名学生归档、超页限制、损坏文件、取消后的迟到导出/保存清理通过。官方SDK处理后的引擎和页面也执行了相同PDF回归。

`miniprogram-ci@2.1.31`独立安装在工具目录，不加入应用依赖；仅调用`getCompiledResult`，不进行真实上传、预览、签名或读取用户密钥。使用SDK内置白名单作为离线服务元数据，代码编译是真实SDK过程。可复现：

```sh
WRITINGSTAR_CI_MODULE=/绝对路径/miniprogram-ci node scripts/verify-weixin-upload.cjs dist/build/mp-weixin /tmp/writingstar-upload
WRITINGSTAR_WEIXIN_ROOT=/tmp/writingstar-upload node --import tsx scripts/verify-pdf-import.mts
WRITINGSTAR_WEIXIN_ROOT=/tmp/writingstar-upload node --import tsx scripts/verify-weixin-pdf.mts
```

初次离线编译统计：主包1,394,790字节、pdf-import 1,876,704字节，其他各包均小于2MiB；具体记录在`outputs/v028-upload-package-sizes.json`，最终交付统计见[交付状态](云端交付状态.md)。Windows IDE的4851KB为用户实测，本机没有运行该Windows IDE；不能将SDK离线检查写成真实预览上传或iPhone验收。
